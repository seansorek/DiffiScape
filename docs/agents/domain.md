# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` contains architecture decision records.

Before exploring an area, read the glossary and any ADRs relevant to it.
If they do not exist, proceed silently; domain documentation is created
when terms or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If an output contradicts an ADR, explicitly identify the conflict.
